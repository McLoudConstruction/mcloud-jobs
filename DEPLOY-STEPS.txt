McLoud Jobs: CRM cleanup (nine changes)

BEFORE YOU DEPLOY
1. Migrations 161 to 166 must already be run in the Supabase SQL Editor.
2. Run this one in the Supabase SQL Editor:
   supabase-migration-167-crm-cleanup.sql
   It is safe to run twice. Run it BEFORE you push the code, because the new screens read
   the new columns. The last thing it prints is a "what needs a human look" table. Read it.
   It lists test records it flagged, types it could not map, and emails shared by more than
   one person. Nothing in it was changed without saying so.

DEPLOY
3. Copy the files in this zip over your repo. The folders match the repo.
4. Push with GitHub Desktop. Vercel deploys. No files to delete.

WHAT CHANGED
- Company do not contact: tick it on a company. Every property under it becomes do not
  contact (shown as "from the company" on the property), and every person under it stops
  getting automated email. Untick it and what it set is lifted. A property you flagged by
  hand stays flagged.
- Email status on a person (Good, Bounced, Left the company, Opted out). A bounce or
  unsubscribe logged as a touch is recorded here too. Setting Bounced or Opted out also puts
  the address on the do not email list. Only an owner can take an address off that list.
- Email confidence on a person: Verified or Pattern guess.
- Duplicate emails: saving a person with an email someone already has shows who, with
  "Save anyway, they share this email". The database refuses it too. People menu, Find
  duplicate emails, lists the four that already got through. Nothing is merged for you.
  Subcontractor people and test records are not checked.
- Touches can be edited or deleted. Any staff member can change a hand logged touch. Only an
  owner can change a touch a bot logged. Fixing a wrongly logged bounce or unsubscribe lifts
  the block it caused. Every edit and delete is kept in the audit log. Stage and next step on
  the record are not changed by deleting a touch.
- One shared type list for properties and people (Multi-Family, Commercial, Office, Retail,
  Industrial, Hospitality, Senior Living, Education, Religious - Churches, Government,
  Recreational, Residential - Homeowner, Residential - Investor, and Real Estate Agent for
  people only). Old values were mapped to it. Most properties now have a type filled in from
  the old vertical field.
- Won: a property set to Won gets a Won on date, an optional linked job and a note. Bots can
  now set Won too, with a note. Only staff can move a prospect out of Won.
- Test records: a Test record box on people, companies and properties. Flagged ones are
  hidden from lists (Show test records brings them back), routes, follow up lists and the
  bot. John Doe, James Smith, Company ABC and anything on example.com or similar were
  flagged for you. Untick the box on any that are real.
- Second phone on people, and a type (Office, Direct, Mobile, Home, Main line, Other) for
  both phones. Excel and vCard imports pick these up. Imports skip people already in People
  by email and tell you who.
- BOT_API.md is updated. Give it to the bots.

AFTER YOU DEPLOY, TRY THIS
- People: open one, set Email status to Bounced, save. Then open Find duplicate emails.
- Companies: tick Do not contact on a test company, open one of its properties, see it
  marked as from the company. Untick it again.
- Try adding a person with an email that already exists. You should see who has it.
- Open a property, set the stage to Won. Fill in the date and what was agreed.
- A touch row: open it, Edit, change the note, Save.

LEFT FOR YOU
- Existing duplicate emails are listed, not merged.
- "residential" (old vertical) and "Mixed Use" (a type) are not on the shared list. They are
  left as typed and shown in the review table. Pick the right type on those properties.
- There is no bulk delete for test records. Flagging hides them.
